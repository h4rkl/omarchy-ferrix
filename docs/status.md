# Status

## 2026-09-20 (application platform and crash isolation)

- **Architecture:** Applications are now independent, supervised Linux processes managed by a new application service, `appd`, instead of in-process pages of one client. The public contract lives in two target-neutral crates: `app-api` (validated `AppId`s, `RuntimeKind`, public JSON `AppDescriptor`s, lifecycle state, and typed errors) and `app-protocol` (role-gated line-delimited JSON, schema v1). The replaceable daemon-to-runtime traits live separately in internal `app-runtime-api`; native executable and namespace configuration remain private to `runtime-native` and are never returned to launcher/application clients. `appd` owns the catalog (`apps/*.json`), single-instance activation, lifecycle, crash records, home-restart backoff, and surface association by kernel-reported pid. On Linux/QEMU it also reconciles launched clients' claimed protocol roles with `SO_PEERCRED` pid ancestry, preventing an app from self-assigning `home`, `tool`, or `compositor`. The full design is in `docs/app-platform.md`. The architecture guard fails if an application, shell, or the core depends on either runtime crate or `appd`, or if `app-api` gains target/implementation conditionals.
- **Namespaced apps (QEMU):** `runtime-native` launches every native app through `ferrix-sandbox`, a safe-Rust (rustix/signal-hook) supervisor that unshares PID, mount, IPC, and UTS namespaces (user namespace when unprivileged), mounts a private `/proc` and tmpfs `/tmp`, sets `no_new_privs`, and runs a PID 1 that forwards signals and reports the exact exit reason. In a headless TCG agent session the home surface and Terminal each started with `sandbox-ready` reporting all four namespaces true; inside the Terminal, `cat /proc/1/comm` returned `ferrix-sandbox`, `/proc` listed only 5 processes, and the prompt hostname (`root@org:…`) reflected the UTS hostname set to the app id.
- **Crash isolation (QEMU):** The Terminal is now `ferrum-terminal`, a separate Wayland client launched by `appd` on a tap. Running `kill -9 -1` inside its shell (confined to its PID namespace) produced, on serial: `client-gone` (pid 700) from the compositor, `app-crashed` `signal:9` from `appd`, `home-crash-notice`, and the compositor refocusing `org.ferrix.home` to the foreground. The compositor, `appd`, and `mobile-core` all survived (zero `compositor-exit`/`compositor-failed`/`appd-failed`/`boot-failed` records). Framebuffers captured under `out/qemu-aarch64/agent/`: `launcher-catalog.png` (catalog-driven launcher), `terminal-namespaced.png` (Terminal in its namespace), `home-after-crash.png` (home with the "Terminal stopped unexpectedly · signal 9" banner), and `qa-terminal-launch.png` (fresh validation after separating the public descriptor from native launch configuration).
- **Compositor:** `mobile-shell` now links `appd` (ret: reports surfaces/focus by `SO_PEERCRED` pid, obeys `Activate`, reconnects on loss) and owns a trusted bottom-edge home gesture (`home-gesture{kind,source,linked}`). New records: `client-gone`, `client-activated`, `home-gesture`, `appd-link`. A regression was found and fixed during bring-up: re-pointing pointer focus on every `refocus()` pinned Smithay's pointer focus to a surface whose client had not yet bound `wl_pointer`, so taps never reached the client; pointer focus now follows real motion and is only re-pointed when the pointer was already over a client (crash recovery).
- **Shared UI:** The software-rendering toolkit and the fullscreen Wayland client runner moved to `ferrum-ui`; `mobile-basic-screen` is now the catalog-driven home surface (launchable tiles go through `appd`; reference entries keep illustrative pages; the home descriptor is never listed as a tile).
- **Validation:** `cargo fmt --check`, workspace clippy with warnings denied (macOS and, via the pinned-container `just linux-check`, aarch64 Linux with `--all-features`), all workspace tests on both hosts (including the `ferrix-sandbox` namespace integration tests, which ran rather than skipped in the privileged container), the privileged-role regression test, `just arch-check`, a fresh `just qemu-build`, and `just qemu-check` (TCG, unplugged-to-charging in 4s, clean power-off) pass. A fresh graphical QEMU run was framebuffer-inspected at the launcher and after launching Terminal through the private native manifest configuration; both rendered correctly.
- **Limitations:** QEMU/mock evidence only; no physical-device claims. Isolation is process- and namespace-based (PID, mount, IPC, UTS, private `/proc` and `/tmp`, `no_new_privs`); apps still run as the session user with access to the shared filesystem and the Wayland/core/appd sockets. Launched-app roles are tied to peer PID ancestry, but compositor/tool authentication remains a bootstrap trust boundary. Portals and permission enforcement, seccomp, cgroup resource limits, a network namespace, a restricted filesystem view, the TypeScript/web and Android runtimes, and supervision of the core and compositor themselves remain future work. The pmOS graphical route was updated to start `appd` but has not received fresh framebuffer validation in this entry.

## 2026-09-20 (Ferrum namespace)

- **Identity:** The project and ship are now Ferrum. Ferrix is the kernel/userspace codename and owns runtime identifiers (`FERRIX_*`, `ferrix.*`, `/run/ferrix`, `/etc/ferrix`, `ferrix.control`, and the `ferrix` guest hostname). Gossan is reserved for a future device image; the current emulator remains the generic `qemu-aarch64` target.
- **Boundary:** Project prose, UI labels, application ids, service files, cache/container names, CI keys, and the bundled architecture skill no longer use the external product's namespace. The generic target id remains `qemu-aarch64`, and all evidence remains QEMU/mock only.

The TCG serial record confirms `ferrix.mode=check`, `/run/ferrix/core.sock`, `ferrix.control`, the deterministic unplugged-to-charging transition, and clean power-off.

## 2026-09-20 (Terminal app)

- **QEMU (Terminal app):** The Terminal tile in `mobile-basic-screen` now opens a working shell instead of an illustrative card. The client spawns BusyBox `/bin/sh` on a PTY through `alacritty_terminal` 0.26 (Alacritty's VT parser/grid/PTY layer, Apache-2.0) and renders the grid with the existing tiny-skia/fontdue software path in Ferrum's Tokyo Night ANSI palette (55x32 cells on the 1080x2340 panel). The client's Wayland loop moved to calloop (`smithay-client-toolkit` `calloop` feature) so the PTY reader thread wakes the UI via a ping source. The session survives Home/back navigation; Enter on an exited shell restarts it.
- **Input:** A touch-first on-screen keyboard (letters, `?123` symbols, shifted symbol row covering all printable ASCII, accessory row `esc tab ctrl ` \ | ← ↓ ↑ →`, sticky shift/ctrl) is part of the Terminal page and shares its geometry with the hit tests. A `virtio-keyboard-pci` device is now attached in graphical/agent sessions; raw `wl_keyboard` evdev codes go through a small hand-rolled US table (`keymap.rs`) because the static musl guest binary does not link libxkbcommon. `just qemu-type TEXT` drives it over QMP.
- **Evidence (QEMU, headless TCG agent session):** serial records `terminal-spawned` (cols 55, rows 32), `terminal-ready` with line `root@ferrix:~#`, `keyboard-input`, and `terminal-exited` (`exit code 130`). Framebuffers under `out/qemu-aarch64/agent/`: `terminal-open.png` (prompt), `terminal-osk-uname.png` (`uname -a` typed entirely by touch-key taps, real `Linux ferrix 6.6.142-0-virt ... aarch64` output), `terminal-keyboard.png` (`echo hw-ok; ls /` via `qemu-type`, colored `ls` output), `terminal-after-ctrlc.png` (sticky ctrl + `c` interrupts `sleep 100`, `^C` shown), `launcher-with-terminal-in-background.png` / `terminal-resumed.png` (session persists across Home), `terminal-exited.png` (yellow exit note), `terminal-restarted.png`. Host preview: `--preview out.ppm --page terminal` renders a canned transcript without a PTY. `cargo fmt --check`, clippy (host and `aarch64-unknown-linux-gnu`), 19 unit tests (OSK layout/coverage, keymap, snapshot colors, a real `/bin/sh` PTY round trip, terminal-page rendering, touch interaction), and `just qemu-check` pass.
- **Limitations:** No key repeat, no selection/copy, no touch scrollbar (drag-to-scroll only, shown as an "N lines up" badge), no bell/title handling, and the keyboard layout is US-only. Redraws are full-frame; under TCG each frame takes tens of milliseconds, which is fine for a reference surface. The product `mobile-shell` now hosts the client by default; the terminal and on-screen keyboard still belong to the reference client rather than compositor-owned shell chrome. No physical-device claims.

## 2026-09-20

- **Layout (mock):** Swiping down from the status bar no longer changes the bar or notification-shade metrics on non-1080 panels. Shell pages previously multiplied layout by `s(1).max(1)`, which truncates to 1px on the 830-wide Cocoa QEMU window and jumped the status bar from 55px to 72px. Every page now uses the same multiply-then-divide scale as the launcher (`v * width / 1080`). Covered by a unit test at 830, 1080, and 1200 widths.
- **QEMU (basic screen):** The ASCII `weston-terminal` reference layout is replaced by `mobile-basic-screen`, a Rust Wayland client (smithay-client-toolkit + tiny-skia + fontdue, software rendering only) that draws a Ferrum-styled (Tokyo Night, JetBrains Mono) basic screen with a GrapheneOS-style status bar, clock, battery/network cards from the mock profile, a six-tile launcher grid, and a gesture pill. Verified by the actual rendered framebuffer at `out/qemu-aarch64/agent/frame.png` after the guest emitted `basic-screen-frame` and `wayland-ready` records on serial; `just qemu-check` still passes headlessly under TCG.
- **Build:** `just qemu-build` now also compiles the guest client for aarch64 musl in a pinned `rust` container (digest and binary hash recorded in the manifest). A host-side `--preview` mode renders the same composition to PPM without QEMU.
- **Input:** The reference surface accepts QEMU absolute-pointer and Wayland touch events with press feedback, six launcher app views, status-bar quick settings, Wi-Fi/Bluetooth mock toggles, a draggable brightness mock, notifications, Back/Home buttons, and top/left/bottom edge gestures. `just qemu-tap` and `just qemu-swipe` provide deterministic QMP input. Verified in QEMU through serial `input-ready`, `input-press`, and `input-release` records plus captured Settings, Notifications, and adjusted Quick Settings framebuffers under `out/qemu-aarch64/agent/`.
- **Pointer feedback (QEMU):** Virtual-tablet input uses a dedicated 32-pixel ARGB Wayland cursor: transparent center, Tokyo Night blue ring and halo, plus an opaque center dot at the exact hotspot. Real Wayland touch contacts remain cursorless. Verified in the actual QEMU framebuffer at `out/qemu-aarch64/agent/touch-cursor.png` with a serial `cursor-ready` record.
- **Window geometry (QEMU, Cocoa):** The on-screen QEMU window previously opened at the wrong size and aspect ratio because QEMU's Cocoa UI pushes its initial 640x480 view size (times backing scale) into virtio-gpu as the preferred mode, so the guest surface ignored `xres`/`yres`; a first attempt that only shrank `xres`/`yres` did not help. `qemu-run.sh` now sizes the panel from the host's visible screen height and backing scale, and the guest init pins Weston to that mode via a generated `weston.ini` modeline. Evidence on this 1920x1080-point Retina host: the window measures 415x932 points (900 content + title bar) at y=37, the guest emits `display-geometry` 830x1800 and `basic-screen-frame` 830x1800, Weston reports `830x1800@60.0, current`, a window capture shows the full portrait launcher, and `just qemu-tap 202 1236` opened `App(Settings)`. Headless agent sessions still render 1080x2340. `qmp.py` now accepts QEMU's row-padded PPM dumps (830-pixel rows carry two padding bytes). GTK backend sizing is unverified.
- **Limitations at that checkpoint:** The clock did not tick and app views were illustrative. Later work above replaced local-only quick-setting state, completed the Catacomb/Smithay decision, made `mobile-shell` the default compositor, and connected rotation. Crash recovery and compositor-owned product chrome remain outstanding. Evidence is QEMU/mock only; no physical-device claims.
