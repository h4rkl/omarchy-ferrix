Phase 0 record for the mobile-connectivity programme (telephony, networking,
Phone/Messages/Contacts, Android runtime, exact-device validation). Evidence
labels in this document: desk review of the checked-in tree plus `mock` host
test runs. No QEMU or physical-device claim is made here.

> audit trail, not as current status. Use `README.md` for the present overview,

## 1. Authority discrepancy and resolution

`AGENTS.md`, `README.md`, and several documents named `docs/baseline.md` and
`docs/plan.md` as the implementation authority and long-term direction, but
neither file exists at `HEAD`.

Finding (git history, read-only):

- Commit `19d43fe` ("docs(plans): consolidate planning materials", owner
  `harkl`, 2026-09-20) deleted `docs/baseline.md` and `docs/plan.md` and moved
  the planning skills from `skills/` to `plans/`.
- Commit `99ce57a` ("docs(plans): define emulator-first mobile Linux roadmap",
  same owner, 21 seconds later) added `plans/baseline.md` and `plans/plan.md`.
- `git diff 19d43fe^:docs/baseline.md 99ce57a:plans/baseline.md` and the same
  comparison for `plan.md` are empty: the moved files are byte-identical to the
  deleted ones.

Resolution: the authority was **moved, not lost**, by the repository owner.
`plans/baseline.md` is the implementation authority and `plans/plan.md` the
long-term direction; baseline wins conflicts. No replacement authority was
invented. This audit repoints the stale references (`AGENTS.md`, `README.md`,
`docs/app-platform.md`, `docs/design.md`, `targets/qemu-aarch64/README.md`,
`crates/ferrix-shell/EVALUATION.md`, `.github/workflows/ci.yml`, and the
`plans/*` skills) to the new paths. Historical `docs/status.md` entries keep
the old wording because they describe what was true when written.

The architecture gate is therefore open: the baseline's boundaries (QEMU
`virt` portability target, postmarketOS substrate, `ferrix-hardware-api`
product boundary, Linux services behind typed adapters, evidence labelling,
board-support gates) apply unchanged to this programme.

## 5. Decisions taken by the lead (recorded as ADRs)

- ADR-001 Telephony service boundary: calls/SMS are **not** forced into the
  `ferrix-hardware-api` state trait; a separate typed service owns them.
- ADR-002 Network model and NetworkManager adapter boundary.
- ADR-003 Contacts ownership, storage, migrations, vCard.
- ADR-004 Service authorization: verified `AppId` via `ferrix-appd`, checked-in
  grants, socket visibility in the sandbox, negative tests.
- ADR-005 Android runtime evaluation constraints and the Brave reference app.
- ADR-006 Evidence labels, mock-control channels, scenario files, and the
  Alpine smoke guest staying offline.

## 6. Decisions that require owner approval before implementation

1. **Baseline/plan text changes.** The ADRs do not edit `plans/baseline.md`
   or `plans/plan.md`. If the owner wants the new services, the grants
   policy, or the Android runtime recorded in the baseline, that edit needs
   explicit approval. Until then the ADRs are subordinate to the baseline.
2. **Android runtime selection and guest kernel changes.** ADR-005 evaluates
   maintained runtimes; installing one into the postmarketOS guest requires
   kernel `binder`/`binderfs` support and large third-party system images.
   The evaluation names the exact packages and sources; the owner should
   confirm before those inputs are pinned into `pmos-build`.
3. **Brave APK source.** Downloading from the official Brave GitHub release
   with a pinned SHA-256 and signing-certificate fingerprint is proposed. If
   the owner prefers a locally supplied APK only, the workflow already
   supports that mode.
4. **Emergency calling.** Not represented as supported anywhere. Any future
   emergency-call design needs a separate review.
5. **OnePlus provisioning.** Read-only discovery remains the only approved
   step; no destructive gate can pass without a device identity.
6. **New dependencies.** `zbus` (D-Bus, MIT) for ModemManager/NetworkManager
   adapters and `phonenumber` (MIT/Apache) for E.164 normalization are
   proposed as popular, maintained, license-compatible crates.
