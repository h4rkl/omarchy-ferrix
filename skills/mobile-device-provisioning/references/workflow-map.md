# Workflow map

One row per checked-in workflow. "Mutates" means the phone's
persistent state or running mode changes. "Gate" is what the workflow itself
enforces; the agent still needs the human's go-ahead per Phase 0 of
`SKILL.md`. Paths are relative to the repository root; outputs are under
ignored `out/` unless stated. Status vocabulary: Implemented, Run on hardware
(date), Stub-tested only (offline PATH-stub tests pass; never run on a phone;
read the script's usage block before use), Not implemented.

## Pixel 9a - build chain (native Linux x86_64, device-free)

"Linux x86_64" means a native x86_64 Linux builder. An ARM64 UTM guest,
x86_64 UTM under CPU emulation, OrbStack/Lima, and cross-build substitutes do
not satisfy this host gate. A digest-pinned `linux/amd64` Docker tool container is
allowed only when Docker runs on a native Linux x86_64 host; it cannot make an
ARM64 host or emulated VM compliant and it must not carry ADB/Fastboot USB
transport. UTM remains suitable for separate Linux smoke tests or QEMU work.

The checked-in `tools/pixel-9a/native-builder.sh` is the supported handoff
wrapper when the native Linux host is remote. It uses the canonical repository
checkout and target-scoped ignored cache/output mounts, and its allow-list
refuses all physical-device and guest-radio workflows. It never mounts USB,
ADB sockets, or Fastboot transport.
